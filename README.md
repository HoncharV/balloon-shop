# 🎈 Balloon Magic — лендінг магазину повітряних кульок

Продажний односторінковий сайт для магазину повітряних кульок у Києві: квіз-воронка,
фотогалерея робіт, готові набори, калькулятор вартості, відгуки, контакти, прийом
заявок у базу та в Telegram, повноцінна адмін-панель із CRM і власною аналітикою.

**Цілі сайту:** генерація лідів → отримання заявок → перехід у Telegram → збір контактів через квіз.

---

## Швидкий старт

```bash
# 1. Залежності
npm install

# 2. Змінні середовища
cp .env.example .env          # Windows PowerShell: Copy-Item .env.example .env

# 3. База даних (потрібен Docker Desktop)
docker compose up -d db

# 4. Схема + початкові дані
npm run db:setup

# 5. Запуск
npm run dev                   # http://localhost:3000
```

**Сайт працює і без пунктів 3–4.** Якщо PostgreSQL недоступний, лендінг усе одно
відкривається — з контентом із `src/data/site-content.ts`. Заявки в такому режимі
надсилаються в Telegram і пишуться в лог сервера, а `/admin` показує, що саме треба
запустити. Саме тому `npm install && npm run dev` дає робочу сторінку одразу.

### Варіант без Docker: нативний PostgreSQL

Docker не обов'язковий. На слабкій машині (мало RAM або диска) PostgreSQL як
звичайна Windows-служба легший: ~400 МБ замість ~5 ГБ і без постійних 2–3 ГБ
оперативної пам'яті.

```powershell
# 1. Встановити
winget install --id PostgreSQL.PostgreSQL.16 --exact --accept-package-agreements --accept-source-agreements

# 2. Створити роль і базу (пароль суперкористувача — див. примітку нижче)
& "C:\Program Files\PostgreSQL\16\bin\psql.exe" -U postgres -h 127.0.0.1 -d postgres -f sql/bootstrap-db.sql

# 3. Далі як зазвичай
npm run db:setup
npm run dev
```

> ⚠️ **Тихий інсталятор winget ставить суперкористувачу `postgres` пароль
> `postgres`**, а не той, що ви вводили (він не вводиться взагалі: маніфест
> запускає `--mode unattended` без `--superpassword`). Саме тому `psql -U postgres`
> із власним паролем дає «помилка автентифікації». Роль застосунку створює
> `sql/bootstrap-db.sql` — вона використовує логін `balloon` / пароль `balloon`,
> тобто **той самий `DATABASE_URL`, що й у `docker-compose.yml`**, і `.env`
> правити не потрібно.
>
> Якщо встановлювали вручну (графічним інсталятором) — просто введіть свій пароль
> у `DATABASE_URL` у `.env` замість `balloon:balloon`.

### Налаштування Telegram (5 хвилин)

1. Напишіть [@BotFather](https://t.me/BotFather) → `/newbot` → отримайте токен →
   покладіть у `TELEGRAM_BOT_TOKEN`.
2. Напишіть [@userinfobot](https://t.me/userinfobot) → отримайте свій `chat id` →
   покладіть у `TELEGRAM_CHAT_ID`.
3. **Обов'язково:** напишіть своєму боту будь-яке повідомлення. Telegram забороняє
   ботам писати першими — без цього кроку сповіщення не прийдуть.
4. Перевірте: `curl http://localhost:3000/api/health` → `"telegram": true`.

Формат повідомлення:

```
🎈 Нова заявка

Ім'я: Олена
Телефон: +380 67 887 33 33
Свято: День народження
Бюджет: 1000–3000 грн
…
```

Якщо токен не заданий — застосунок не падає: заявка зберігається в базі, а в лог
пишеться попередження.

### Про міграції

Схема застосовується через `prisma db push`, а не через `prisma migrate deploy`:
у репозиторії навмисно немає теки `prisma/migrations`. Причина — схема містить
`TEXT[]`, `JSONB`, `DATE` та дев'ять enum-типів, і згенерований руками SQL-файл
міг би розійтися з `schema.prisma`, через що Prisma Client почав би очікувати
неіснуючі колонки. `db push` бере схему як єдине джерело правди.

Коли проєкт піде в продакшен і знадобиться історія змін:

```bash
npm run db:migrate -- --name init      # створить prisma/migrations/ і застосує її
# після цього в CI/CD використовуйте:
npx prisma migrate deploy
```

Довідниковий DDL усієї схеми лежить у `sql/schema.sql` — він еквівалентний
`schema.prisma` і призначений для тих, хто піднімає базу руками через `psql`.

### Ключові архітектурні рішення

- **Один файл контенту.** `src/data/site-content.ts` використовують і сід, і fallback
  без бази. Тому дані ніколи не розходяться.
- **Лендінг ніколи не падає через БД.** Усі читання йдуть через `readDb()` із
  підстановкою контенту за замовчуванням.
- **Заявка не губиться двічі.** Якщо БД недоступна, але Telegram працює — користувач
  бачить успіх, а лід іде менеджеру. Помилку показуємо лише коли впало й те, й інше.
- **Доставка заявки ніколи не блокує відповідь.** Збій Telegram не робить заявку невдалою.
- **Межа client/server тримається на типах.** Клієнтські компоненти імпортують типи з
  `@/types/site`, а не з `@/lib/content` — щоб Prisma Client фізично не міг потрапити
  в браузерний бандл.
- **`/admin/login` — єдина відкрита сторінка.** Захист стоїть в одному layout для
  route-групи `(dashboard)`, а не в middleware: Edge runtime не має `node:crypto`, і
  друга реалізація підпису сесії була б джерелом помилок.

| **Аналітика** | Відвідувачі за сьогодні / 7 / 30 днів / всього, джерела трафіку, найпопулярніші сторінки, перегляди квіза, кількість заявок |
| **Налаштування** | Телефон, Telegram, Instagram, адреса, карта, графік роботи, розмір знижки |

Статуси заявок: **Новий → В роботі → Виконано**.

Сесія — `httpOnly` cookie, підписана HMAC-SHA256 (`AUTH_SECRET`), типово на 12 годин.
Пароль ніде не зберігається: порівняння з `ADMIN_PASSWORD` іде через
`timingSafeEqual`, тому за часом відповіді не можна вгадати складність пароля.

### Завантаження фото

Дозволені формати: **PNG, JPEG, WebP, AVIF, GIF**, до **5 МБ**.

**SVG заборонено навмисно.** SVG — це XML, який може містити `<script>`, а файли
віддаються з того ж домену, тому завантажений SVG став би stored XSS з повним
доступом до сесії адміністратора. Додатково сервер перевіряє «магічні байти» вмісту,
а ім'я файлу генерує сам (`crypto.randomUUID()` + розширення з MIME-типу) — щоб
`../../` у назві не міг вивести запис за межі `public/uploads`.

## Аналітика

Власний лічильник, без Google Analytics і без сторонніх скриптів.

**Як працює:** `<AnalyticsTracker />` у кореневому layout один раз на сесію пише
cookie `bm_vid` (на рік) і `bm_sid` (на 30 хвилин), а на кожен перехід і подію робить
`POST /api/track`. Дані лягають у таблиці `visitors`, `page_views`, `analytics_events`.

**Джерела трафіку** визначаються за `document.referrer` (з урахуванням `utm_source`):
Telegram, Instagram, Google, Facebook, TikTok, Viber, YouTube, переходи з інших
сайтів або прямий захід.

**Події:** `quiz_view`, `quiz_start`, `quiz_complete`, `calculator_open`,
`calculator_submit`, `lead_submit`, `telegram_click`, `phone_click`, `gallery_open`,
`package_order`, а також глибина скролу 50%/90%.

Обидві таблиці мають індекси за `createdAt`, тому звіти не деградують із ростом даних.
Дані збираються **без** сторонніх сервісів, тому cookie-банер не потрібен — але якщо
додасте рекламні пікселі, він стане обов'язковим.

## SEO

- `sitemap.xml` (`src/app/sitemap.ts`) і `robots.txt` (`src/app/robots.ts`) —
  генеруються кодом; `/admin` і `/api` закриті від індексації двічі: у `robots.ts`
  і через `robots: { index: false }` у layout адмінки.
- **Open Graph / Twitter card** — зображення 1200×630 генерується на етапі збірки
  (`src/app/opengraph-image.tsx`).
- **Meta tags** — title/description/keywords/canonical у `src/app/layout.tsx`.
- **JSON-LD** — `LocalBusiness` з адресою, телефоном, годинами роботи та `sameAs`
  на Instagram/Telegram, плюс `WebSite`. Розмітка екранується від `<script>`-ін'єкції.

Для продакшену обов'язково задайте `NEXT_PUBLIC_SITE_URL` — інакше в canonical,
sitemap і Open Graph потрапить `localhost`.

## Деплой у Docker

```bash
# Образ застосунку (Next.js standalone, non-root user, HEALTHCHECK)
docker build -t balloon-magic .

# Повний стек: база + застосунок
docker compose --profile full up -d --build

# Схема застосовується з хоста (образ навмисно не вміє мігрувати базу —
# щоб контейнер застосунку не потребував прав на зміну схеми)
npm run db:setup
```

`docker compose up -d db` піднімає **лише** базу: профіль `full` вимкнений типово,
щоб не збирати образ застосунку під час звичайної роботи над кодом.

Том `balloon-uploads` зберігає завантажені фото між перезбірками образу.
У контейнері виставлено `TZ=Europe/Kyiv` — межі «сьогодні» в аналітиці
рахуються за київським часом.

## Формула калькулятора

Це бізнес-логіка, узгоджена з власником магазину. **Числа більше не зашиті в код** —
вони лежать у конфігурації квіза й редагуються в **`/admin/quiz`**. Формула — у
`src/lib/calculator.ts`, ваги — у `src/data/quiz-config.ts` (типові значення).

```
гостей           = явна кількість або середина діапазону
кульок           = clamp(⌈гостей × кульок-на-гостя × множник свята⌉, 10, 120)
вартість кульок  = кульок × ціна за кульку
разом            = кульки + надбавка за декор + надбавка за свято + доставка
```

Де які числа задаються:

| Що | Де в `/admin/quiz` | Типово |
|---|---|---|
| Ціна за кульку | Крок «Рівень оформлення» → `Ціна кульки` | 45 / 60 / 85 грн |
| Кульок на гостя | Крок «Рівень оформлення» → `Кульок на гостя` | 0.8 / 1.6 / 2.4 |
| Надбавка за декор | Крок «Рівень оформлення» → `Надбавка` | 0 / 250 / 900 грн |
| Множник свята | Крок «Яке свято?» → `Множник обсягу` | весілля 1.35, корпоратив 1.2 |
| Надбавка за свято | Крок «Яке свято?» → `Надбавка` | весілля +600, корпоратив +300 |
| Скільки гостей у розрахунку | Крок «Скільки гостей?» → `Гостей у розрахунку` | 8 / 15 / 35 / 60 |
| Доставка | Секція «Загальні» | 250 грн, безкоштовно від 3999 грн |

Підсумок округлюється до 50 грн, а `priceMax` = +25% — діапазон виглядає чесніше за
одну цифру, яка потім зростає. Рекомендований набір: до 1800 грн → START, до 3600 грн
→ STANDARD, далі PREMIUM.

Той самий код виконується і в браузері, і на сервері, тому клієнт ніколи не побачить
цифру, якої немає в заявці.

## Редагування квіза (`/admin/quiz`)

Що можна змінювати **вільно**:

- заголовок і підзаголовок усієї секції квіза;
- заголовок, підказку й текст кожного кроку;
- підпис, підказку, емодзі, порядок і видимість будь-якого варіанта;
- додавати варіант назад — але лише зі списку дозволених кодів;
- усі числові ваги калькулятора (див. таблицю вище).

### Головне обмеження

У заявці зберігається **внутрішній код** варіанта (`WEDDING`, `UP_TO_10`), а не текст.
Коди прив'язані до типів у базі даних (`enum` у `prisma/schema.prisma`). Тому:

- **підпис** («Весілля» → «Весілля під ключ») змінюється вільно — у базі лишається `WEDDING`;
- **порядок** і **видимість** змінюються вільно — вони ніде не зберігаються;
- **новий код** додати не можна. Це потребує зміни `enum` у схемі БД: інакше
  `prisma.lead.create` впаде на невалідному значенні й **заявка не запишеться**.

Тому в редакторі поле коду варіанта доступне лише для читання, а «Додати варіант»
пропонує вибір із тих кодів, що вже є в структурі бази.

Якщо справді потрібен новий код (наприклад, «Річниця»):

1. додайте значення в `enum HolidayType` у `prisma/schema.prisma`;
2. додайте його в `ALLOWED_OPTION_VALUES.HOLIDAY` у `src/data/quiz-config.ts`;
3. виконайте `npm run db:push`;
4. після цього варіант можна буде додати з адмінки.

### Кроки, які не можна вимкнути

`CONTACTS`, `HOLIDAY`, `GUESTS` і `DECOR` вимкнути не можна — це перевіряє схема
(`ALWAYS_ENABLED_STEP_KEYS`). Причина технічна: `calculatorLeadSchema` вимагає поля
`holidayType`, `guests`, `decorLevel`, а без форми контактів нема де взяти ім'я й
телефон, тобто зникає сенс воронки. Вільні до вимкнення — `AUDIENCE`, `BUDGET`, `DATE`.

Кнопка **«Скинути до типових»** повертає форму до `DEFAULT_QUIZ_CONFIG` (без збереження —
потрібно натиснути «Зберегти»). Це аварійний вихід, якщо конфігурацію зіпсовано.

## Безпека

- Заявки: обмеження 5 на 10 хвилин з однієї IP + приховане honeypot-поле + перевірка
  «занадто швидкої відправки» (менше 1.2 с — бот).
- Логін: 8 спроб на 10 хвилин, порівняння через `timingSafeEqual`, однаковий час
  відповіді при хибному логіні й паролі.
- Завантаження: білий список MIME + перевірка магічних байтів + згенероване ім'я файлу.
- Уся вставка користувацького тексту в HTML (Telegram-повідомлення, JSON-LD) проходить
  через екранування (`src/lib/html.ts`).
- Запити до БД — тільки через Prisma; сирий SQL (агрегація аналітики) — виключно з
  плейсхолдерами.
- Заголовки `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options` — у
  `next.config.ts`.

**Обмеження, які варто знати:** ліміти частоти живуть у пам'яті процесу, тому на
кількох репліках вони множаться. Для розподіленого деплою замініть реалізацію
`src/lib/rate-limit.ts` на Redis — інтерфейс залишиться той самий.

## Типові проблеми

| Симптом | Причина й рішення |
|---|---|
| `/admin` показує «База даних недоступна» | Запустіть `docker compose up -d db`, потім `npm run db:setup` |
| Заявки не приходять у Telegram | Не надіслали боту жодного повідомлення — Telegram забороняє писати першим. Перевірте `/api/health` |
| `prisma generate` падає при `npm install` | Немає файлу `.env` або порожній `DATABASE_URL`. Скопіюйте `.env.example` |
| Ukrainian text у OG-зображенні — квадратики | Не завантажились шрифти з `public/fonts`. Вони в репозиторії; перевірте, чи тека не потрапила в `.gitignore` |
| Зміни в адмінці не видно на сайті | Лендінг кешується (ISR 60 с). Зачекайте хвилину або перезапустіть `npm run dev` |
| `Error: listen EADDRINUSE :3000` | Порт зайнятий: `npm run dev -- -p 3001` |
| Логін в адмінку «проходить», але ви знову на формі входу — без жодної помилки | Cookie сесії позначена `Secure`, а сайт відкрито по `http`. Це станеться при доступі за LAN-IP (`http://192.168.x.x:3000`), бо `localhost` браузери вважають безпечним джерелом. Рішення: задайте `NEXT_PUBLIC_SITE_URL="http://192.168.x.x:3000"` (тоді `Secure` не ставиться) або підніміть HTTPS і вкажіть адресу з `https://`. Прапорець виводиться з `NEXT_PUBLIC_SITE_URL`, не з `NODE_ENV` — див. `src/lib/cookies.ts` |
| `psql: FATAL: пароль не пройшов автентифікацію для користувача "postgres"` при нативному встановленні | Тихий інсталятор winget ставить пароль `postgres` (не той, що ви вводили). Див. розділ «Варіант без Docker» вище |

### Windows + PowerShell

- `npm` і `npx` заблоковані як `.ps1` політикою виконання — викликайте `npm.cmd` / `npx.cmd`.
- Зміни `PATH` не зберігаються між викликами оболонки. Перед командою, якій потрібен
  щойно встановлений інструмент:
  ```powershell
  $env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [Environment]::GetEnvironmentVariable('Path','User')
  ```
- Кирилиця, передана як аргумент CLI, спотворюється. Файли з не-ASCII текстом
  створюйте редактором, а не через `echo`.
